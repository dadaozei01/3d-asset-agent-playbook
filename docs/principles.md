# 核心原则

这些原则适用于任何 3D 软件、任何风格。它们来自实际制作中反复出现的问题，而不是理论。

## 1. 文档是默认值，判断力优先

本仓库给出的是经过验证的默认做法。遇到下列情况，Agent 应当偏离并说明理由：

- 你有把握更好、更简单或更稳的方案；
- 现场条件与文档假设不同（软件版本、场景结构、用户目标）；
- 按文档做会明显得到更差的结果。

偏离时说一句“文档建议 A，这里我用 B，因为……”，然后去做。不要为了“合规”放弃更好的结果，也不要悄悄偏离。

## 2. 先看现状再动手

- 动手前读清楚：场景里已有什么、当前文件是什么、单位与朝向、用户是否有未保存的修改。
- 不删除或覆盖用户已有的东西。需要替换时先隐藏或备份，结束时说明。
- 用户手动删改过的内容（例如自己删掉的地面）是用户的决定，不要“帮忙”恢复。不确定时先问。

## 3. 每一步都要看图

3D 结果不能只靠数字验证。

- 每次有意义的修改后渲染或截图，用眼睛判断，而不是假设成功。
- 至少看：正面、侧面/45°、背面、近景细节。背面和近景最容易漏。
- 节点接错、遮罩全为 1、贴图没加载这类问题，看图一眼就能发现；看数字往往发现不了。
- 怀疑某个效果是否生效时，临时把它改成醒目的颜色（纯红、发光）定位，验证后改回。

## 4. 先对齐预期，再追细节

- 第一版求“方向对”，不求完美。尽快给用户看，让用户纠偏。
- 用户的反馈往往很短（“太像玩具”“像老虎斑纹”），要把它翻译成具体的技术原因再改，并在回复里说出你的理解。
- 用户说“之前的感觉是对的”时，回到之前的版本只去掉被指出的问题，不要整体推翻。

## 5. 非破坏、可回溯

- 保留可编辑的源：程序化材质、修改器、原始高精度贴图。交付用的烘焙版本是“输出”，不是唯一副本。
- 破坏性操作（应用修改器、合并、烘焙）在副本上做。
- 文件、贴图使用相对路径，整个资产文件夹移动后仍能打开。

## 6. 用对工具，不被工具绑定

- 优先使用当前环境已验证可用的 MCP / 脚本通道。
- AI 生成（贴图、模型）是素材来源之一，不是唯一来源。生成结果几乎都需要后处理：无缝化、去除不要的元素、调色。
- 一项能力在某软件里不可用时，先找等价做法（例如用另一种数据通道传参），而不是放弃效果。

## 7. 为最终平台而做

- 制作过程中就想着交付：引擎里看不到软件专有的节点效果，最终都要变成网格、UV 和贴图。
- 面数、贴图分辨率、材质槽数量都按目标平台预算来定，并在交付时报告。

## 8. 诚实汇报

- 汇报时说清楚：做了什么、看图验证了什么、哪些没验证（例如“FBX 未在 UE 实测导入”）。
- 花了用户的额度（生成贴图、云端模型）要说明消耗了什么。
- 出现意外（误删、超时、效果没生效）直接说，然后修。
